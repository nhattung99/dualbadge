# Rome research

The requested ROME_and_Arena_Knowledge_Base.md was absent from the workspace, its parent project directory, and the attachment directory. This research uses official sources.

- [Rome SDK](https://github.com/rome-protocol/rome-sdk-ts) documents EIP-1193 writes through submitRomeTx. Its Solana lane sends a wallet-signed Solana instruction, with the caller derived by Rome from the signing payer's public key. The canonical address is the low 20 bytes of Keccak-256 over the raw 32-byte public key.
- [Official scaffold](https://github.com/rome-protocol/create-rome-app) uses one Solidity contract, registry-derived config and a browser wallet for each lane. The current upstream template uses the SDK's v1 transaction path. Its web template uses Vite. DualBadge adapts the write path to the requested Next App Router.
- [Aerarium](https://github.com/rome-protocol/aerarium/blob/main/docs/INTEGRATION.md) demonstrates both callers sharing a Solidity lending market. [Rome DEX](https://github.com/rome-protocol/rome-dex) demonstrates shared liquidity and lean account sets across the two lanes.
- [Registry](https://github.com/rome-protocol/rome-registry) and [Rome CLI](https://github.com/rome-protocol/rome-cli) identify Hadrian as EVM chain 200010 on Solana devnet. EVM gas uses USDC. Rome documents bridging test USDC from a source testnet rather than a Rome faucet. Use the registry and live preflight for endpoints, gas and program details.
- [Rome Solidity](https://github.com/rome-protocol/rome-solidity) supplies CPI interfaces. This registry needs no application CPI, token transfer, or native value.
- A synthetic caller is an EVM address for Solidity storage purposes. ERC721 and ERC1155 could store ownership keyed by that address, but wallet display, transfers, approvals, receiver behavior and marketplace recognition were not validated for Phantom. A custom non-transferable registry only relies on protocol-authenticated msg.sender.
- The Arena ideas page lists an **EVM and Solana wallets** category, including **Identity Manager**. The public registration client exposes the Builder sign-in gate, form fields and length limits, and Hadrian contract-linking flow. The signed-in submission itself is pending. [Arena ideas](https://arena.mainnet.romeprotocol.xyz/ideas#ideas-both-wallets) · [Arena app registration](https://arena.mainnet.romeprotocol.xyz/apps/new)
